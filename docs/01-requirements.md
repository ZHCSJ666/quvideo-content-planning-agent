# 需求与成功标准

## 用户与交付

用户为跨境电商运营人员。默认案例：ROAM 350 合成便携杯，在 48 个模拟业务小时内，以不超过 100 个模拟成本单位，交付德国、美国市场各两条 20 秒短视频**内容方案**。数量可配置为每市场 1–4 条。产品为演示设定，未证实保温时长、防漏、价格或促销；系统不得补造这些事实。

交付包包含目标人群、市场策略、不同创意、对应语言脚本、连续分镜、素材引用、行动引导、总费用与排期。产物为 JSON + Markdown，不生成或声称已生成视频。实际媒体是项目自制 SVG 示意素材，市场人群是可替换的演示 brief，不是国家文化定论，也不证明真实转化率。

## 硬约束与软目标

- 必须补齐预算、截止时间才执行收费业务工具；保留同一任务等待补充。
- 不擅自减少数量、取消市场、扩充预算或延长期限。
- 成功要求：全部请求的任务产物存在、通过结构和语义检查、费用/期限合规、保存确认成功。
- 在可行范围内提高表达质量与市场适配；不宣称找到全局最优解。
- 真实模型选择动作、观察真实工具返回、调整下一步。控制流程允许固定骨架，工具选择不能被固定分支伪装。
- 缺资料、失败、质量不合格、预算/期限不足时允许重规划；无可行方案必须返回未完成和恢复条件。
- 每任务最多三次生成尝试，每次 run 有调用上限；显式 resume 可增加有限调用额度。错误、拒绝、重试都消耗调用次数。

## 状态与重复执行

任务状态：`running`、`waiting_input`、`completed`、`incomplete`。视频产物状态：`generated`、`rejected`、`approved`；工具失败在独立 Trace 中记录，不能把该次调用记为成功。

相同任务 ID 和相同初始请求再次提交，返回已有结果且不执行更多工作。不同请求不能覆盖既有 ID。失败续跑显式发起，保留累计费用、时间和未失效成果。改变任务的素材、策略或档位只失效该任务的依赖产物；旧输出仍可在 Trace 中审计。

## 模拟成本与时钟

费用均为整数模拟单位，不是法币。素材检索、脚本制作、审核、保存的费用与耗时在 `data/rules.json`。计划和估算本身在模拟账本中免费；控制模型的真实 token 用量另行记录，不冒充 API 发票费用。费用表描述本项目的**方案制作流程**，不包含实际视频拍摄/渲染。

执行前检查 `已消耗 + 剩余预计`，执行后按工具实际结果入账。估算不会重复扣费，失败不退款已完成步骤。已知模拟服务故障消耗 2 单位和 10 分钟；实际模型调用异常按该模拟服务的已尝试费用保守记账，真实供应商是否计费需查其账单。

时钟按顺序执行的模拟分钟累计，不等待现实 48 小时。外部等待由 `resume --wait-minutes` 明确推进；默认为 0，表示演示中没有推进业务时钟。API 超时是独立的现实秒数限制。当前版本不实现业务并行排程。

## 验收覆盖

正常完成；分别缺预算/截止时间及补齐；暂时/持续工具失败；超预算重规划/不可行停止；重复执行；失败续跑。扩展验证覆盖素材缺失、质量拒绝、保存失败、期限紧张、调用上限、非法参数和文件路径。至少两条真实模型执行路径用于证明决策行为；离线 Mock 仅证明流程与工程约束。

## 范围外

成片生成、真实投放、线上生产部署、真实市场效果评估、多租户权限、分布式工作流、任意商品自动研究不属于本次交付。GitHub 提交需要用户指定仓库与题号，并提供最终仓库 URL、commit SHA；原始试题与凭据不得加入仓库。
